# 需求文档（MC/DC 真值表生成器）

> 本文件沉淀产品的硬性功能需求与约束，算法的每次改动都不得违背以下条款。
> 任何"优化"（如减少用例数）都必须在满足全部约束的前提下进行。

## 1. MC/DC 正确性（核心）
- 对每个变量 V，结果真值表中**必须存在至少一对测试用例**，使得：
  1. 两用例仅在变量 V 上取值不同（Hamming 距离 = 1，其余变量取值完全相同）；
  2. 两用例的 `out`（判定）结果相反。
- 即每个变量都满足"独立影响（Independent Influence）"，符合 MC/DC 定义。

## 2. 测试用例必须相邻（硬约束，不可篡改）⚠️
- 上述每对"覆盖变量 V 的用例"**必须落在结果表的相邻两行（连续行）中**。
- 也就是说，变量 V 的影响对 `(行 i, 行 i+1)` 必须是相邻的，不能分散在非相邻行。
- 这是产品明确要求，任何"减少用例数"的优化都**不得**以牺牲相邻性为代价。
- 允许在相邻对之间出现"跳转行"（与上一行可相差多个变量、非单变量翻转），
  但跳转行本身不用于覆盖任何变量；被覆盖变量的影响对始终保持相邻。

## 3. out 列严格 0/1 交替（硬约束）
- 结果表的 `out` 列必须是严格的 `0,1,0,1,…` 或 `1,0,1,0,…`，即任意相邻两行的
  `out` 取值必相反。

## 4. 用例数最小化（在约束 1~3 之下）
- 在满足「MC/DC 正确 + 相邻 + 严格交替」三个硬约束的前提下，尽量压缩总用例数
  （链式重叠、复用支点行等），使真值表最小。
- 例：`a & (b | c | d | e | f)` 在该约束集下的最小解为 **10 行**
  （out 严格交替，每个变量的影响对均相邻），这是该表达式的理论下界。
- 注意：**不能**为了更少用例而破坏"相邻"或"严格交替"约束；若两者冲突，
  优先保证相邻与交替，用例数其次。

## 5. 起始基准
- 支持"从 0 开始 / 从 1 开始"两种首行取值约定（对应 `startFromTrue`）。

## 6. 非功能性
- 变量数上限 `MAX_VARIABLES = 10`，防止 2^n 真值表爆炸导致 OOM。
- 解析支持 `& && and` / `| || or` / `! ~ not` / 括号，优先级 NOT > AND > OR。
- 算法输出须通过自检：out 严格交替；每个变量高亮对确为 Hamming-1 / 判定反转对。
